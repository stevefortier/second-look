# Bird extremes v1

Private experimental bank, not human aesthetic ratings. First three score keys are deliberately identical: `beautiful`, `important`, `impressive` = +1 for bird photographs, −1 for other photographs. They encode a constructed bird preference, not the merit, beauty, strength, importance or abilities of any person. `strong` describes only the photograph's compositional visual force. No faces, demographic features, identities, body types, human scores or visual review are used.

**Source and licensing.** Original COCO 2017 JPEGs, with per-photo ID, S3 URL, original Flickr image and photo-page link, annotation-supplied Creative Commons license name/URL/ID, captions and categories in `sources.jsonl`. No original JPEG was modified. Photograph ownership remains with the individual creators; the bank does not grant a blanket license. See COCO's official terms (https://cocodataset.org/#termsofuse) and individual license URLs. Noncommercial, share-alike and no-derivatives conditions vary; check the creator page, attribution and intended use before further distribution. COCO is the annotation source, not the photographer. Flickr creator names are not provided in the COCO archive.

**Sampling.** Both official train2017 and val2017 are pooled; the new train/test are not COCO's official splits. Native width and height must each be ≥256, license ID 1–6. All IDs in the legacy 320-photo bank, including its known false positives, are excluded. A visible label means a noncrowd instance of area ≥1% of the image. Birds require a visible COCO bird label, two distinct caption texts mentioning avian terms, and no caption matching the conservative representation/artifact rejection vocabulary. Nonbirds require no bird label or detected avian caption term: visible nonbird animal takes priority, then visible person without animal labels, then a place term without person/animal labels. These are annotation and text screens, not proof that every caption or label is correct. Source candidates are SHA-256-ranked using the published seed. No post-hoc visual judgments.

**Deduplication and splits.** Reject repeated COCO IDs, Flickr-photo groups, original file hashes, decoded RGB hashes, and 64-bit grayscale dHashes within Hamming distance 5 of an accepted photo globally. No creator/event metadata in the source permits full scene/photographer-level separation. Stratify by four mutually exclusive categories; within each category, hash-sort groups, hold out exactly the first fifth and separately hash-order rows within each split. Use manifest for exact counts and hashes. Filename and score schemas match the project reader.

**Proxy measurement.** Pillow bilinear-resize decoded RGB to 96×96 in stored raster orientation; normalize each channel to [0,1]. Y=.299R+.587G+.114B; E=hypot(forward horizontal difference of Y, forward vertical difference of Y); replicate boundary pixels for differences. `strong`: multiply luminance interdecile range by mean edge magnitude weighted near the four rule-of-thirds lines (Gaussian width 0.07 in normalized frame coordinates). `bright`: mean Y. `saturated`: mean per-pixel HSV saturation. `warm`: mean R−B. `detailed`: mean E. `contrasty`: population standard deviation of Y. `busy`: fraction E>0.10. For each visual proxy assign −1 below the training lower tercile, +1 above the training upper tercile, and 0 otherwise, using the same frozen thresholds on test. Raw measurements per original and exact thresholds/formulas are included. No actual strength inference is made.

**Reproduction.** From `/home/scratch/Workspaces/second-look`, use `bash scripts/fetch-bird-extremes.sh` then `.venv/bin/python -m scripts.bird_extremes_bundle verify`. `manifest.json` pins archive, selection seed, software versions and ordered split hashes; `SHA256SUMS` pins all other deliverables including every original. Downloads use 24 streaming workers, retry/backoff, per-photo atomic file+metadata checkpoints and a persistent disk cache in `work/bird-extremes/`. Repeating an interrupted run resumes completed photos, not partial HTTP bodies. To rebuild from scratch use a fresh project checkout with the same source files and versions; leave an existing verified output untouched. Explicit publication: `bash scripts/publish-bird-extremes.sh`.
